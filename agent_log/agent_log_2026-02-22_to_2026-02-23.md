## 2026-02-23 — Refactor PlantNotificationJob for Scalability

Extracted per-user notification work into a separate job so Sidekiq can parallelize across workers instead of blocking one thread for all users.

### Files Created
- `app/jobs/send_user_notification_job.rb` — Handles a single user's notifications (email via `deliver_later`, push inline, then `mark_notification_sent!`)

### Files Modified
- `app/jobs/plant_notification_job.rb` — Simplified to a lightweight dispatcher that enqueues `SendUserNotificationJob` per eligible user

### Why
- Push notifications (`WebPush.payload_send`) are synchronous HTTP calls that blocked the entire job
- A crash mid-way would skip remaining users and risk re-notifying already-processed ones
- Now each user is an independent job: failures don't cascade, and Sidekiq processes users in parallel
